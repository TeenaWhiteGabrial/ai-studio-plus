# AI Coding 平台 - 产品需求规格说明书

## 0. 前言

### 0.1 文档目的

本文档为 AI Coding 平台的统一产品需求规格说明书，整合管理端（Admin）、控制台（Console）、门户网站（Portal）三个子系统的完整需求。

### 0.2 子系统定位

| 子系统 | 项目名称 | 定位 | 主要用户 |
|--------|---------|------|---------|
| Portal | AI Coding 资源门户网站 | 面向所有用户的资源发现与下载平台 | 访客、注册用户、控制台用户 |
| Console | AI Coding 控制台 | 面向认证用户的工作台，提供资源上传、任务管理、产出统计 | 通过团队认证的企业用户 |
| Admin | AI Coding 管理端 | 面向平台管理员的后台，提供用户管理、内容审核、数据报表 | 超级管理员、运营管理员、部门管理员 |

### 0.3 共享架构说明

#### 资源类型体系

所有资源类型在 Portal 统一展示，在 Console 上传管理，在 Admin 审核。资源架构如下：（Rules)

| 资源类型 | 主表 | 版本表 | 审核状态 | 说明 |
|----------|------|--------|----------|------|
| Skill | `skill` | `skill_version` | 待审核/已通过/已拒绝 | AI 技能包，支持多版本 |
| MCP | `mcp_server` | `mcp_server_version` | 待审核/已通过/已拒绝 | MCP 服务器配置，支持多版本 |
| Plugin | `plugin` | `plugin_version` | 待审核/已通过/已拒绝 | 插件包，支持多版本 |
| 教程 | `tutorial` | `tutorial_version` | 待审核/已通过/已拒绝 | 教程文档，支持多版本 |
| 安装包 | `installer` | `installer_version` | 待审核/已通过/已拒绝 | 安装程序，支持多版本 |

#### 用户权限体系

```
组织架构：
  部门 (Department)
      │
      └── 团队 (Team) ── 成员 (User)
                           │
                           └── teamId 属于部门下的某个 team

用户归属规则：
  - 用户必须先有 deptId，才能有 teamId
  - deptId 为必填，teamId 为选填
  - 一个用户只能属于一个团队
  - 一个团队只能属于一个部门
```

# 第一部分：门户网站（Portal）

## 1. Portal 项目概述

### 1.1 项目定位

面向所有用户的资源发现与下载平台，提供 Skill、MCP、Plugin、教程、安装包、视频等资源的浏览、搜索、预览、下载功能。

| 角色 | 说明 | 权限 |
|------|------|------|

### 1.3 核心目标

- 首页。一个简洁的大输入框
- 资源中心。所有资源集中地
- 文档中心。AI驱动的知识库
- 技术社区。问答、文章、评论、点赞、收藏等内容
- 个人中心。

# 第二部分：控制台（Console）

## 3. Console 项目概述

### 3.1 项目定位

面向通过团队认证的用户，提供上传资源、发布文章、API Key 获取、任务管理（每日任务录入、日常任务、自动发邮件）、项目管理及 AI 产出统计等工作台。

1、资源管理（管理员上传）
2、技术社区（文章发布、问答）
3、任务统计（项目、任务、产出）

### 3.2 目标用户

| 角色 | 说明 |
|------|------|
| 控制台用户 | 已通过团队认证的企业用户 |

### 3.3 核心目标

- 提供便捷的 API Key 管理
- 记录和统计个人工作数据（任务、项目、产出）
- 管理个人上传的资源和收藏
- 统计个人 AI 产出效能（代码行数、文档数）

### 3.4 多人协作说明

- **项目管理**: 任何人可创建项目，所有人可见并可录入任务
- **一人多项目**: 一个用户可同时参与多个项目

#### 4.2 工时任务比指标定义

```
指标 A: 每工时完成任务数
  = 已完成任务数 / 总投入工时

指标 B: 每任务平均工时
  = 总投入工时 / 已完成任务数

统计口径:
  - 范围: 本周 / 本月 (Tab 切换)
  - 只统计"已完成"状态的任务
  - AI 参与度不影响工时计算
```

# 第三部分：管理端（Admin）

## 5. Admin 项目概述

### 5.1 项目定位

面向平台管理员的管理后台，提供用户管理、团队管理、部门管理、内容审核、数据报表、运营配置等功能。
测试的缺陷维护。

### 5.2 目标用户

| 角色 | 角色代码 | 说明 | 权限范围 |
|------|---------|------|---------|
| 超级管理员 | `SUPER_ADMIN` | 最高权限 | 所有功能 |
| 运营管理员 | `OP_ADMIN` | 日常运营 | 网站配置、首页运营、审核资源、全部统计报表 |
| 部门管理员 | `DEPT_ADMIN` | 部门级管理 | 本部门用户管理、本部门团队管理、本部门统计报表 |

**角色说明：**
- 超级管理员拥有系统所有权限
- 运营管理员负责平台运营工作（网站配置、首页运营、审核资源），可查看全部统计报表
- 部门管理员仅能管理自己所属部门的用户和团队，可查看本部门统计报表。**分配部门管理员角色时需同时指定其所属部门**

### 5.3 核心目标

- 高效管理平台用户、团队和部门
- 审核用户上传的内容，确保质量
- 查看平台数据，了解运营情况
- 配置首页运营内容，提升用户体验

```

  - 一个用户只能属于一个团队
  - 一个团队只能属于一个部门

  - 超级管理员：可见所有用户
  - 运营管理员：不可见用户列表（无用户管理权限）
  - 部门管理员：仅可见本部门用户（deptId = managed_dept_id）
```

## 8. Admin 用户操作权限流程

### 8.1 部门管理员分配流程

```
1. 超级管理员进入"系统管理" → "角色管理"
2. 选择要分配部门管理员的用户
3. 选择角色："部门管理员"
4. 指定管理的部门（managed_dept_id）
5. 保存
```

### 8.2 用户添加到部门流程（部门管理员）

```
前提：用户 deptId=null
1. 部门管理员进入"用户管理"
2. 筛选"未分配部门"用户
3. 点击"添加到部门"
4. 系统自动将用户 deptId 设置为管理员的 managed_dept_id
5. 保存
```

### 8.3 添加成员到团队流程（管理员）

```
入口A - 在团队管理中添加：
  1. 管理员进入"团队管理"
  2. 选择某个团队，点击"添加成员"
  3. 从本部门未分配团队的用户列表中选择
  4. 确认添加

入口B - 在用户管理中分配：
  1. 管理员进入"用户管理"
  2. 筛选本部门且 teamId=null 的用户
  3. 选择用户，点击"分配到团队"
  4. 选择本部门下的某个团队
  5. 保存
```

### 8.4 移出团队成员流程

```
1. 管理员进入"团队管理"
2. 选择某个团队，进入团队成员列表
3. 选择成员，点击"移出团队"
4. 确认后，该成员的 teamId 置为空，deptId 保留
```

## 附录 C: 产出数据表结构 (member_output)

> 来源: docs/output.sql
> 说明: 以下字段由数据团队写入，Console 仅做读取展示。

```sql
CREATE TABLE `member_output` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键',
  `user_id` bigint NOT NULL COMMENT '用户ID',
  `user_name` varchar(50) DEFAULT NULL COMMENT '用户名（开放 API 使用）',
  `stat_date` date NOT NULL COMMENT '统计日期',
  `prd_count` int DEFAULT '0' COMMENT 'PRD文档数（旧字段）',
  `api_count` int DEFAULT '0' COMMENT 'API接口数',
  `java_lines` int DEFAULT '0' COMMENT 'Java代码行数（旧字段）',
  `frontend_lines` int DEFAULT '0' COMMENT '前端代码行数（旧字段）',
  `remark` varchar(500) DEFAULT NULL COMMENT '备注',
  `project_root_name` varchar(255) DEFAULT NULL COMMENT '项目根目录名（用于标识产出所属项目）',
  `prd_doc_count` int DEFAULT '0' COMMENT 'PRD 文档数量',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `data_model_doc_count` int DEFAULT '0' COMMENT '数据模型文档数量',
  `api_doc_count` int DEFAULT '0' COMMENT 'API 接口文档数量',
  `java_file_count` int DEFAULT '0' COMMENT 'Java 文件数量',
  `java_code_lines` int DEFAULT '0' COMMENT 'Java 代码行数',
  `core_biz_service_count` int DEFAULT '0' COMMENT '核心业务服务数量',
  `entity_count` int DEFAULT '0' COMMENT '数据库实体数量',
  `frontend_component_count` int DEFAULT '0' COMMENT '前端组件数量',
  `frontend_page_count` int DEFAULT '0' COMMENT '前端页面数量',
  `frontend_common_component_count` int DEFAULT '0' COMMENT '前端公共组件数量',
  `ts_code_lines` int DEFAULT '0' COMMENT 'TypeScript 代码行数',
  `frontend_code_lines` int DEFAULT '0' COMMENT '前端代码行数',
  `sql_script_count` int DEFAULT '0' COMMENT 'SQL 脚本数量',
  `test_file_count` int DEFAULT '0' COMMENT '测试文件数量',
  `total_code_lines` int DEFAULT '0' COMMENT '总代码行数',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uq_user_date_project` (`user_name`,`stat_date`,`project_root_name`),
  KEY `idx_stat_date` (`stat_date`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_user_name_date` (`user_name`,`stat_date`),
  KEY `idx_project_date` (`project_root_name`,`stat_date`),
  KEY `idx_user_project_date` (`user_id`,`project_root_name`,`stat_date`),
  KEY `idx_stat_date_user` (`stat_date`,`user_id`)
) ENGINE=InnoDB AUTO_INCREMENT=100 DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='成员产出表';
```

> 展示说明:
> - 代码行数: 优先使用 `java_code_lines` + `ts_code_lines` + `frontend_code_lines`，参考 `total_code_lines`
> - 文档数: 使用 `prd_doc_count` + `data_model_doc_count` + `api_doc_count`
> - 筛选维度: `user_name` + `stat_date` + `project_root_name`
