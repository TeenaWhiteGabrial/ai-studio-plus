# AI Coding 管理端 - 产品需求规格说明书

## 1. 项目概述

### 1.1 项目定位
面向平台管理员的管理后台，提供用户管理、团队管理、部门管理、内容审核、数据报表、运营配置等功能。

### 1.2 目标用户

| 角色 | 角色代码 | 说明 | 权限范围 |
|------|---------|------|---------|
| 超级管理员 | `SUPER_ADMIN` | 最高权限 | 所有功能 |
| 运营管理员 | `OP_ADMIN` | 日常运营 | 网站配置、首页运营、审核资源、全部统计报表 |
| 部门管理员 | `DEPT_ADMIN` | 部门级管理 | 本部门用户管理、本部门团队管理、本部门统计报表 |

**角色说明：**
- 超级管理员拥有系统所有权限
- 运营管理员负责平台运营工作（网站配置、首页运营、审核资源），可查看全部统计报表
- 部门管理员仅能管理自己所属部门的用户和团队，可查看本部门统计报表。**分配部门管理员角色时需同时指定其所属部门**

### 1.3 核心目标
- 高效管理平台用户、团队和部门
- 审核用户上传的内容，确保质量
- 查看平台数据，了解运营情况
- 配置首页运营内容，提升用户体验

| M02-F08 | 重置密码 | 作为管理员，我希望重置用户密码，以便帮助用户找回 | 生成随机密码并通知用户 | 超级管理员 |
| M02-F09 | 批量导入 | 作为管理员，我希望批量导入用户数据，以便提高效率 | 批量导入用户，部门、团队为选填 | 超级管理员 |
| M02-F10 | 分配角色 | 作为管理员，我希望为用户分配角色 | 选择角色，其中部门管理员需同时指定管理部门的部门ID | 超级管理员 |

#### 2.2 用户归属规则

```
用户归属关系：
  - 用户必须先有 deptId，才能有 teamId
  - deptId 为必填，teamId 为选填
  - 一个用户只能属于一个团队
  - 一个团队只能属于一个部门

用户筛选逻辑：
  - 超级管理员：可见所有用户
  - 运营管理员：不可见用户列表（无用户管理权限）
  - 部门管理员：仅可见本部门用户（deptId = managed_dept_id）
```

```
任务统计指标：
  - 每工时完成任务数 = 已完成任务数 / 总投入工时
  - 每任务平均工时 = 总投入工时 / 已完成任务数

统计范围：
  - 本周 / 本月（Tab 切换）
  - 只统计"已完成"状态的任务
  - AI 参与度不影响工时计算

数据来源：daily_task 表（每日任务模块）
```

|------|------|------|
| id | bigint | 主键 |

### A.2 团队表 (sys_team)

| 字段 | 类型 | 说明 |

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |

| 角色代码 | 角色名称 | 说明 |
|---------|---------|------|

## 附录 B: 用户操作权限流程

### B.1 部门管理员分配流程

```
1. 超级管理员进入"系统管理" → "角色管理"
2. 选择要分配部门管理员的用户
3. 选择角色："部门管理员"
4. 指定管理的部门（managed_dept_id）
5. 保存
```

### B.2 用户添加到部门流程（部门管理员）

```
前提：用户 deptId=null
1. 部门管理员进入"用户管理"
2. 筛选"未分配部门"用户
3. 点击"添加到部门"
4. 系统自动将用户 deptId 设置为管理员的 managed_dept_id
5. 保存
```

### B.3 添加成员到团队流程（管理员）

```
入口A - 在团队管理中添加：
  1. 管理员进入"团队管理"
  2. 选择某个团队，点击"添加成员"
  3. 从本部门未分配团队的用户列表中选择
  4. 确认添加

入口B - 在用户管理中分配：
  1. 管理员进入"用户管理"
  2. 筛选本部门且 teamId=null 的用户
  3. 选择用户，点击"分配到团队"
  4. 选择本部门下的某个团队
  5. 保存
```

### B.4 移出团队成员流程

```
1. 管理员进入"团队管理"
2. 选择某个团队，进入团队成员列表
3. 选择成员，点击"移出团队"
4. 确认后，该成员的 teamId 置为空，deptId 保留
```
