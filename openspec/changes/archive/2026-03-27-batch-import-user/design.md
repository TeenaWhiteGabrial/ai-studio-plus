## Context

当前用户管理页面仅支持单个创建用户，管理员在以下场景中面临效率问题：
- 新员工批量入职时需要创建多个用户
- 系统初始化时需要导入大量用户数据
- 定期从 HR 系统导出 Excel 后手动录入

现有条件：
- 前端：Vue 3 + Element Plus
- 后端：Spring Boot + MyBatis
- 用户表已存在，包含 username, password, real_name, department, email, status 字段

## Goals / Non-Goals

**Goals:**
- 提供 Excel/CSV 文件上传功能，前端解析文件内容
- 提供标准导入模板下载
- 支持批量导入用户（建议单次不超过 1000 条）
- 显示导入结果统计（成功/失败数量及明细）
- 数据校验：用户名唯一性、必填字段、邮箱格式
- 后端提供批量创建用户接口，仅 SUPER_ADMIN 可访问

**Non-Goals:**
- 不支持修改现有用户数据（仅新增）
- 不支持导入角色分配（导入用户后需手动分配角色）
- 不处理文件存储（解析后不保留文件）

## Decisions

### 1. 前端文件解析方案
**决策**: 使用 `xlsx` 库 (SheetJS) 在浏览器端解析 Excel 和 CSV 文件

**理由**:
- 成熟的开源库，支持多种 Excel 格式
- 前端解析可减轻服务器压力
- 可即时预览数据，用户体验更好
- 避免大文件上传到服务器的带宽消耗

**替代方案考虑**:
- 后端解析：需上传文件到服务器，增加网络传输和存储成本
- 仅支持 CSV：降低用户体验，Excel 更常用

### 2. 批量接口设计
**决策**: 后端接口一次性接收完整用户数组，事务性处理

**理由**:
- 简单直接，易于实现和维护
- 事务保证数据一致性
- 导入失败可返回每条数据的错误原因

**替代方案考虑**:
- 分批处理：增加复杂度，当前需求不需要
- 异步任务：适用于超大批量，当前场景不必需

### 3. 数据校验策略
**决策**: 前端初步校验 + 后端严格校验

**理由**:
- 前端校验提供即时反馈（必填项、邮箱格式）
- 后端校验确保数据安全（用户名唯一性、权限）
- 双重校验保证数据质量

## Risks / Trade-offs

**风险**: 大量数据导入时前端解析可能卡顿
- **缓解**: 限制单次最大导入数量（1000 条），超出时提示分批

**风险**: 部分成功场景的处理复杂性
- **缓解**: 返回每条数据的处理结果，前端展示成功/失败明细

**风险**: 用户名冲突导致部分导入失败
- **缓解**: 提供"跳过重复"选项（当前版本暂不实现，提示用户处理）

**风险**: Excel 格式多样性导致解析问题
- **缓解**: 提供标准模板，仅支持常见格式 (.xlsx, .xls, .csv)

## Migration Plan

1. 前端安装 `xlsx` 依赖包
2. 创建导入模板文件并放置在 public 目录
3. 实现前端导入组件和弹窗逻辑
4. 后端实现批量创建用户接口
5. 前端对接接口并展示导入结果
6. 测试：正常导入、部分失败、全部失败场景
